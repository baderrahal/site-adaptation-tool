# Rules

This file is the only source of the rules for this tool. Code, tests and prompts point here and hold no rule of their own.
Every rule has an id. A test that proves a rule names the id in its function name.

## Reader rules

- **R1 Read only.** A reader never changes the file it opens. The Revit command makes no transaction and closes every document it opened with no save. The Python readers open files in read mode. The placer of R83 to R88 is not a reader. It is the one part that changes a model, only the open document and only in its real run.
- **R2 Round to 3 decimals.** Every coordinate or measure written to JSON is rounded to 3 decimals. Negative zero is written as 0. The one exception is the Excel columns El @ Entry and Height, which keep 4 decimals because a step count switches on thresholds that sit within 0.001 of real values.
- **R3 Small output.** Each JSON file holds only the fields listed for it below. No raw geometry dumps, no curve control points, no binary data.
- **R4 Revit prototypes.** prototypes.json lists every family name, type name, key parameters, bounding box, insertion point, rotation, level, plus the project survey point and base point. Lengths are in metres and angles in degrees. Key parameters default to a fixed list and can be replaced by a key-parameters.txt file next to the add-in DLL.
- **R5 CAD files.** layers.json lists every layer with entity counts. plots.json lists polylines and blocks of model space with layer, coordinates and attribute text. texts.json lists the text of the drawing with position. Coordinates are in drawing units, written as found. The LINE and ARC pieces on the plot line layers named in the config (rule R20) are plot geometry. Lines are split where one ends on or crosses another, and every closed face has its vertices, area and any arcs (centre and radius). Pieces that bound no closed face are written to plots.json as plot_open with their segments, so nothing on those layers is dropped. What a closed face becomes is rule R22.
- **R6 CAD reader library.** The CAD reader uses the ACadSharp NuGet package. If ACadSharp fails to open a real sample DWG, the fallback is an ezdxf script on a DXF export, and the round log says which path was used.
- **R7 PDF licence.** The PDF reader uses pdfplumber, MIT licence. PyMuPDF is not allowed, in code or in requirements.
- **R8 PDF output.** pdf_labels.json lists the text labels with their page position, except the margin stamp and the key plan text, which are counted in pdf_rows.json. pdf_shapes.json lists vector lines and rectangles with position. Positions are in PDF points from the top left of the page. The table rows are rule R23.
- **R9 Excel output.** coords.json holds the rows of the coordinates sheet keyed by column header. The header row is the first row with a cell containing Plot No. and rows above it are not data. Data stops at the first fully empty row, at a row with a cell starting with Total, or at a row with no plot number. coords_headers.json holds the headers found and the sheet row they came from. Each row carries sheetRow, its row number in the sheet. coords_extra.json holds the non-empty rows above the header and from the end of the table down, with sheet row numbers, and the formula of each derived column in the first plot row. A missing sheet is an error that lists the sheets present, and a sheet with no Plot No. cell is an error.
- **R10 No invented data.** Tests use the smallest dummy file built in code. A reader is not called confirmed on real data until a real sample exists in the repo or the person has run it. Until then it stops at the dummy test stage.

- **R16 Revit links.** For a project document, prototypes.json also lists every Revit link instance under links, loaded or not. An entry holds the link file name, its transform (origin in metres, rotation in degrees counter clockwise in plan from the link X axis, a mirrored flag, and the three axis vectors, because a mirrored transform cannot be rebuilt from rotation alone), the instance Name as rawName and every instance parameter as parameters, text and long text included. The fields plotNumber, prototype, ffl, steps and case are read from RRE_ZZ_SP_Plot-Number, RRE_ZZ_SP_Prototype, RRE_ZZ_SP_Prototype-FFL, RRE_ZZ_SP_Number-of-Steps and CASE. nameParts splits the clean name on " | " into plot, prototype, steps, facadeColor and designOption. Rule R38 says how the clean name is found. A value the source does not hold is written as null and a line is added to the errors of that entry. Nothing is guessed, so the prototype parameter and the villa file name may differ. The name and the parameters live on the link instance, so a link that is not loaded still has them and stays in the list with an errors entry. With the option once, the contents of a linked file are written once, under the top level array linkedFiles, one entry per file name, read from the first loaded link of that file. Every link entry keeps contentsRef with the file name. A linkedFiles entry holds instances, links inside the file and errors. Instances have the shape of a prototypes row plus mirrored, and carry every instance and type parameter, shared ones included, not only the key list from R4. The instance value wins when a type parameter has the same name. Instance points are in the linked model's own coordinates and the transform of the link takes them to the host. Links inside a file are read one level deep under the links of its linkedFiles entry. Anything deeper is counted as deeperLinks and not read. A transform inside a nested entry is relative to the file that holds it. The option --link-contents none|once, default none (rule R39), is given as a flag to ReaderOptions or as a line in reader-options.txt next to the add-in DLL. none writes no linkedFiles and no contentsRef. A problem on one element or one link is listed under errors and does not stop the rest.
- **R17 Walls, floors and ramps.** For a project document, prototypes.json also lists every wall instance under walls, every floor placed directly in the host document under floors, and every ramp instance under ramps. A wall has type name, location, length, height when Revit holds one (the Unconnected Height parameter) and every instance parameter. A floor has type name, level name, heightOffset from the level, topElevation, thickness, area, sketchBoundary, corners, cornersSource, slope, plotNumber, unit and every instance parameter. The corners are rule R34 and R35 and the plot fields are rule R37. topElevation is the level elevation plus the offset, in the internal coordinates that every other point in the file uses. sketchBoundary is the outer loop of the floor sketch as vertices in order, closed from the last back to the first. It was called boundary before round 7 and its z is not an elevation (rule R34). The outer loop is the one that encloses the most area. A curve that is neither a line nor an arc is cut into straight pieces. Every arc is also listed under arcs with the index of its edge, centre, radius and ccw, the sweep from start to end seen from above. Floors inside links are not read. A ramp has type name, location when Revit gives one, bounding box and every instance parameter. A location holds the ends of a line or arc, plus centre and radius for an arc, and never control points. Parameters are sorted by name and a name held twice keeps both, the later one as Name (2). Values follow R2.

## Round 4 rules

- **R18 Main is protected.** The hook in .claude/hooks/guard-main.sh blocks git commit on main and any git push from main or to main. The branch is that of the repo each git command acts on: the folder it runs in after a cd or Set-Location earlier in the same command, or the path given with git -C, starting from the cwd of the hook input. The folder the session started in does not count, so a commit on a branch in any clone or worktree passes and a commit on main anywhere is blocked. The hook splits the command on its separators outside quotes, so words inside a message or a heredoc are no command, and it walks the command given to bash -c or powershell -Command the same way. Work happens on a branch and lands by pull request. A session that starts outside the repo has no hooks.
- **R19 Explode.** The CAD reader explodes every block reference, nested ones too, down to lines, arcs, circles, polylines, hatches and points, to a depth of 16 and with a stop on a block that contains itself. Each piece in pieces.json has layer, handle, world coordinates, the handles of the insert chain, and any attributes and extended data. Layer 0 inside a block takes the layer of its insert. Mirrored inserts flip arc direction and bulge. layers.json holds the entity count of each layer before and after exploding, the extents of the kept pieces, and totals. An array insert is read for its first cell and counted.
- **R20 Layer filter.** config/cad_layers.json holds keep and drop lists of layer names, with * and ? wildcards and no case. Drop wins over keep. A layer on neither list is kept and shown as unlisted. Pieces and texts on a dropped layer, and everything inside an insert on a dropped layer, are counted and not written. The same file names the plot line layers and the plot label layers. A config that is missing falls back to no filter and the default plot layers.
- **R21 Texts and xrefs.** texts.json also holds text inside exploded blocks, block attribute values and MULTILEADER text, each with its handle and insert path. layers.json lists every xref with name, saved path and whether the file was found next to the drawing, and the run goes on without it. Reader notes are grouped with counts.
- **R22 Plot labels.** A plot label is a text on a plot label layer whose last line is a number, with any lines or words before it as the label type. A closed face that holds exactly one label is a plot_shape in plots.json with plot, type and centre. A face with no label or with several goes to other_faces.json with the reason no_label or many_labels and is not deleted. plots.json summary counts shapes, plots, other faces, labels outside every face, labels with no number and duplicate numbers.
- **R23 PDF rows.** pdf_rows.json holds one record per table row with the five values plot, code, type, n and e, and page, block and row. Blocks are read left to right and rows top to bottom, so a plot that runs from the foot of one block to the top of the next stays in order, and continued counts those plots. Text that sits in a block but is not a row is listed as rejected. A number with no decimal point is kept as found and listed in odd. The margin stamp, the key plan text and short strokes outside the table are counted and left out. Touching pieces of one table rule are one line.
- **R24 Link table.** link_table.py joins CAD plots, PDF rows and Excel rows by the official plot number into links.json. The CAD label is found with the shift of rule R28. It checks each join by location, where every PDF point must lie inside the CAD plot of the same number or within the tolerance of its edge. Each plot also records which CAD plot holds the points and the number difference. conflicts.json lists every disagreement, duplicate and missing match and nothing is resolved silently. extents.json compares the extents of every drawing and says yes or no for overlap.
- **R25 Full run.** full_run.py runs each reader in place on the real files and gives each file its own output folder and a time limit of 600 seconds. A failure or a timeout is recorded with its exact text and the run goes on with the next file. DWG files under 01_Output, .bak files and Excel lock files are not read, and the skipped files are listed. The skip list of rule R29 applies too. After the readers the run also runs the link table, the second source check and the face reasons as stages when their inputs exist, each with its own output folder and time limit, and a stage that cannot run is listed with the reason.
- **R26 Harness files.** CLAUDE.md is under 200 lines. steps/PROGRESS.md is at most 60 lines. The top entry of steps/log.md fits one page and has Goal, Done, Checked, Remains, Known bugs, Next and Your turn in that order.

## Round 5 rules

- **R27 Link summary.** python/link_summary.py reads prototypes.json and prints plain text and writes link_summary.json. It counts the links of the host document by file and by prototype parameter, the mirrored links per prototype, the rotation values, CASE against mirrored and against rotation, the links whose Prototype-FFL equals the link origin Z within 1.5 mm, and the plot numbers on more than one link. ffl is read as metres and only a plain number is read. A part the file cannot give, such as every part that needs the fields of R16 in an old file, is null and listed under notComputable with the reason. Links inside linked files are not counted. It also counts the floors by type and the walls by type, and for the ramp floors (type name holds Ramp) how the z of the sketch outline relates to the top elevation and the level, and when floors carry cornersSource how many use shape editing, how many report a slope and how many use neither. With the option --excel coords.json (the output of excel_reader.py) it checks the villa links against the schedule rows by plot number. It reports whether plots match one to one, whether the prototype equals the Excel unit and the unit in the villa file name, whether CASE with the mirror flag fixes one rotation, whether the step count equals the Excel steps, and how the link origin height and the Prototype-FFL parameter compare with the Excel FFL. It also checks the floors per plot (rule R49). It reads only prototypes.json and the Excel rows.

## Round 6 rules

- **R28 Plot number shift.** The PDF and Excel plot numbers are official and the baseplan CAD labels are lower. config/plot_numbers.json holds one shift per neighbourhood (IMC 10, IMD 11), a note that says the direction in words, the pattern that takes the neighbourhood code from the source file name (IMC or IMD) and the search range. Official number minus shift gives the CAD label. The neighbourhood of a plot comes from the file names of its PDF sheets and Excel books. A plot with no code, with two different codes or with a number that is not numeric is a conflict (no_neighbourhood, neighbourhood_mixed, not_numeric) and is not joined. After the join the location check of R24 runs with the same tolerance. A plot that fails is tested again with the shifts one lower and one higher (the search range), the shift that fits is recorded as shiftFound and the best fit wins. Every plot whose shiftFound differs from the config is written to conflicts.json as shift_edge with the config shift and the shift found, and none is fixed silently. A plot that fits no shift stays a location conflict. Two official plots that end on one CAD plot are a cad_claimed_twice conflict. CAD plots no official plot points to are listed as cad_unclaimed. A missing config stops the link step.
- **R29 Master Plan roles and skip list.** The full run reads the Master Plan drawings that config/project.json gives a role to: masterplan, the current master plan, and villaBlocks, the drawing the unit blocks are read from. drawings.previousMasterplan, the master plan that masterplan replaced, is kept for reference and is not read. Neither is any drawing in drawings.skip. 221229_MP-SK-01-03-001_R06_0001.dwg is skipped because it is an identical copy of R06_0000 with the same layer counts and the same handles. Each drawing that is not read is listed in full_run_summary.json under skipped with its reason in full. A reason in drawings.skip wins over the reason of the previous master plan. The file name of the current master plan is written in the config only, and a test checks that no Python file holds it.
- **R30 No plot type against unit type check.** The CAD plot type (8 types such as DP4 or VL4) and the unit type of the schedules (14 types such as DT3 or VD2) are many to one by design and are never compared. The CAD type is written to links.json as the info field cadType. The check that the PDF unit type equals the Excel unit stays, as type_mismatch.
- **R31 Second source check.** python/second_source.py compares the closed plot faces of the baseplan with the closed plot faces of the master plan drawing named by drawings.masterplan in config/project.json by location and area. The layers named in config/second_source.json give the faces. A closed polyline is a face, loose lines are noded and polygonized and equal faces from different layers count once. Two faces match when the overlap divided by the union is at least minOverlap, best overlap first, one to one. The report holds counts in second_source.json, with secondFile as the file name the CAD reader wrote into pieces.json, and under details the plot numbers and areas of the unmatched and differing faces, never a coordinate. Counts are matched, only in the baseplan, only in the second drawing, how many matched faces differ in area by more than areaPercent, and how many unmatched second faces hold two or more baseplan faces. Nothing is fixed or changed.
- **R32 Workbook survey.** excel_reader.py with the flag --survey reads a workbook in place and writes survey.json with every sheet, its header row (the row with Plot No. when there is one, else the row with the most text cells in the first 30 rows), its row count and data row count, the header texts, the headers that contain the word plot, and the plot number column when a header names one. For a sheet with a plot number column and an area column it counts how many plots have a CAD plot of the same area (within 1 percent) as found and minus each shift of R28, which tells whether the numbers follow the CAD labels or the official numbers. The full run reads the masterplan workbook in the Master Plan folder this way.
- **R33 Face and label reasons.** python/face_reasons.py groups the other faces and the labels outside every face of the baseplan by reason and writes other_reasons.json with counts, plot numbers and distances and no coordinates. Many label faces are grouped as a consecutive run, a run plus one outlier or not consecutive. No label faces are grouped by area as sliver, small or large and list the stray labels within 30 m. A label outside every face is grouped as a road or buffer label (type word ROW or Buffer), near an unlabelled face, near a labelled face or far from every face (more than 10 m). Nothing is fixed.

## Round 7 rules

- **R34 Floor corners.** Every floor has corners, a list with one [x, y, z] per corner. The units and the coordinate space are those of every other point in the file (metres, internal coordinates, R2 rounding) and z is the real level of that corner, so two corners of a ramp can differ in height. sketchBoundary is the outline of the floor sketch and replaces the old key boundary. Its z is the height of the sketch plane that Revit gives for Sketch.Profile and it is never an elevation. In the first real run every ramp floor had one z on all its outline points, 0 on 44 floors (the level) and 150 on 293 floors, and none equalled the top elevation. The code only converts feet to metres, so the value comes from Revit. Read levels from corners only. Shape editing points that are not corners are listed under shapePoints when a floor has some. A floor that gives no corner has no corners key and a line in errors.
- **R35 Corner source and slope.** cornersSource is shapeEditor or boundary. It is shapeEditor when the slab shape editor of the floor is enabled and holds at least 3 vertices of type corner, and the corners are those vertices with their own z. Otherwise it is boundary, the start point of each edge of the outer loop with z equal to topElevation. A boundary corner set is flat, so it says nothing about a slope. slope holds parameter, the Slope parameter as Revit holds it or null, and arrow, true when the floor sketch holds a slope arrow, false when it holds none and null when that could not be read. The add-in dialog and link_summary.py count the floors that use shape editing, report a slope or use neither.
- **R36 Spot elevations.** The document entry of a project has spotElevations, one entry per spot dimension of the style spot elevation, in the host document only. An entry holds elementId, origin, value (the top value of the annotation, else the bottom value, null when neither reads), view (the name of the view it sits in) and target (the id of the element the first reference points to, null when the API gives none). A model with none has an empty list. A failure is a line in errors that starts with spotElevations and does not stop the other sections.
- **R37 Floor and wall plot numbers.** The Plot parameter holds the unit and the plot number joined by a dash, for example VD2-2441. plotNumber is the digits after the last dash and unit is the text before it, both as text. A floor always has both fields, null when the Plot parameter is missing or does not read this way. A value that does not read this way gets a line of its own in errors, a missing parameter is counted by type under rule R50. A wall has them only when it holds a Plot parameter, and a wall whose value does not read this way gets null and a line in errors.
- **R38 Link name parse.** rawName is the Name of the link instance exactly as Revit gives it. The parts of nameParts come from the clean name. The clean name is the shared parameter RRE_ZZ_SP_RVT-Name when it holds text. Without it the clean name is the raw name with the file name in front of the first part removed (everything up to the first " : " in that part) and the location suffix removed from the end (" : location" and the words after it, such as Not Shared). A name with neither stays as it is. The clean name is split as R16 says.
- **R39 Link contents default.** The default of --link-contents is none. The reader reads the link instances, with their name, parameters and transform, and not what is inside the linked files. The option once stays available through a line in reader-options.txt and writes linkedFiles and contentsRef as R16 describes.
- **R40 LandXML reader.** python/landxml_reader.py streams a Civil 3D LandXML file with a low memory parser (expat, one megabyte at a time) and keeps points and faces in numpy arrays, never in lists of strings or one string of the whole file. The point order inside a P tag is northing, then easting, then elevation, and the arrays hold easting, northing, elevation. A P id is not assumed to run from 1, a face names point ids and is mapped through them. A face with a missing point id or a text that is not three whole numbers is counted as bad and dropped. For each surface the reader writes a folder named after the surface with points.npy, faces.npy (visible faces as indexes into the points) and summary.json (name, point count, face count, visible, invisible and bad face counts, bounding box, z range and the z range the file declares), and one landxml_summary.json with the coordinate system code and the unit. The output stays in sample_output and out of git. The file is read in place.
- **R41 Invisible faces.** A face tagged i equal to 1 is a hole or lies outside the boundary. It is counted in the summary and never reaches faces.npy or the lookup, so a point inside it has no level.
- **R42 Surface lookup.** python/surface_lookup.py loads a surface and answers, for a surface and a point (easting, northing), the z interpolated from the visible triangle that holds the point, or None when no visible triangle holds it. A grid index sized from the triangles keeps 1500 points to seconds. A point on an edge or a vertex counts as inside, the triangle with the lowest index answers and both neighbours give the same z, so the answer is one number. A triangle with no area is left out. The same index gives the distance from a point to the nearest visible triangle up to a limit, or None beyond it.
- **R43 Surface roles.** config/road_surfaces.json lists every surface of the file with a role. EXISTING_11.5 Sqkm is ground. Top Surface-02 is road, because Bader decided it is the finished road for the ramps. The other five are design and none of them is confirmed. At most one surface has the role road. The design tables count every surface that is not ground, the road included. The file also holds the ramp type names, the distance bands and the names of the input files, and its note says the same as this rule. A ramp corner that does not match the road is a design choice and is never forced to match. A surface in the file that the config does not name is reported as notInConfig and is left out of the ramp level tables, but the role report of rule R48 still measures it. A configured name the file lacks is reported as missingFromFile. Only Bader edits the roles and no code writes this file.
- **R44 Ramp road levels.** python/ramp_levels.py reads the floors of the project document of prototypes.json whose type name is one of the ramp types. Rule R47 says where the four corners and their levels come from. Every design surface and every ground surface is looked up at every corner. ramp_road_levels.json holds per ramp the plot number and unit (the Plot parameter is the unit, a dash, the plot number), the floor type, the top elevation in shared elevation and per corner the corner level, the road level, their difference, the level of each design surface that covers it and of each ground surface. road_levels_summary.json holds counts only: ramps by covered corners 0 to 4 over all design surfaces and per surface, for two covered corners whether they are neighbouring or opposite along the outline, and the difference between the floor top and each surface. The option check-plot writes plot_check.json for one plot, with every corner against the floor top, the link Prototype-FFL and the other floors of the plot, because the street corner is not known.
- **R45 Gap bands.** For each design surface, the corners no design surface covers and the ramps with no covered corner are counted by the distance to the nearest visible triangle of that surface in the bands up to 1 m, up to 5 m, up to 20 m and more. A ramp is counted by its nearest corner. The counts tell whether a surface is missing or the road has a gap. Nothing is guessed.
- **R46 Full run stages and second check.** python/full_run.py runs the LandXML reader as the stage landxml with a limit of 600 seconds, then the stage road_levels, which is skipped with its reason when the reader did not finish ok or an input file is missing. A failure keeps its exact text and the run goes on. python/road_check.py checks by other methods: it counts the P and F tags of every surface from the raw bytes, reads every point and visible face again with regular expressions and compares them with the arrays, finds the triangle and z of a random sample of 200 corner points with shapely and a plane fit and compares them with the lookup, and opens 6 random ramps by plot number, recomputes their corners from the raw prototypes.json and compares the levels with the ramp file. The seed is written to road_check.json.

## Round 8 rules

- **R47 Ramp corner levels.** A ramp floor has four corners. The x, y and z of each corner are the corners key of the floor plus the survey point offset, which is shared position minus position on each axis, and the z is the corner level. A floor without corners falls back to the x and y of sketchBoundary with the top elevation as the level, and the run counts those floors. The old key boundary is never read. A ramp with no corners or with a number of corners other than four is left out of the tables and counted. Per corner the ramp file adds the corner level, the road level of the surface with the role road and the difference, corner level minus road level, or none where the road does not cover the corner. The run counts the covered corners by absolute difference in the bands up to 10 mm, up to 30 mm, up to 100 mm, up to 300 mm and more, and for ramps with exactly 2 covered neighbouring corners how many have both, one and none within 30 mm, by floor type. The second method uses the spot elevations of the document. It counts the spots whose origin lies within 5 cm of a ramp corner in plan, the corners that have such a spot and the spread of spot z minus corner z. These counts go to the log and no level or coordinate goes to git.
- **R48 Role proposal.** The ramp test also writes role_proposal.json. For every surface the LandXML file lists it gives the corners covered, the corners within 30 mm of the corner level, the median absolute difference, the share of invisible faces and the median of corner level minus surface at the covered corners, next to the role the config gives. The proposal is ground when the surface covers at least 95 percent of the corners and the median of corner level minus surface is above zero. Of the other surfaces the one with the most corners within 30 mm is road, when it has at least one and no other surface ties it. Every other surface is unknown. A config role design fits a proposal of unknown. Any other difference between the config and the proposal writes one warning line per surface to the run log, with the surface name, the config role and the proposed role. The proposal never changes config/road_surfaces.json.
- **R49 Floor count per plot.** python/link_summary.py checks that every plot with a ramp floor has exactly one Generic 150mm floor, one yard floor and one ramp floor, a ramp floor being one whose type name holds Ramp. Floors are grouped by plotNumber, and by the Plot parameter in a file of the old shape. The plots that miss one or have more than one are listed by plot number, with the floor kind and the count found, in link_summary.json under floorSummary.floorCount, and the text output gives the counts. A yard floor reaches a plot only through its plot number. When no yard floor has one, the yard count per plot is not computed and the check lists that under notComputable with the number of yard floors and the number of plots with a ramp floor.
- **R50 One line for floors with no Plot parameter.** In the errors of a project document the floors that hold no Plot parameter get one line per floor type and not one per floor. The line says how many floors had no Plot parameter, the type name and up to 5 element ids, and it says first 5 when there are more. The lines come after the other floor lines in type name order. A floor with no type name is grouped as (no type). A floor whose Plot value does not read as unit and number keeps its own line (rule R37).

## Round 9 rules

- **R51 Shared coordinates.** Every geometry field added in round 9 is in shared coordinates in metres, which are the internal coordinates plus the survey point offset on each axis, its shared position minus its position. The rotation to true north is not applied. Every existing field stays in internal coordinates and none of them changes. When the survey point cannot be read the shared fields are left out and one line in errors says so.
- **R52 Floor measurements.** A floor also has typeId, levelElevation, topElevationRange (lowest and highest z of the edges of the real top faces from HostObjectUtils.GetTopFaces), bottomElevationRange (the same for the faces of the solid that look down), boundingBox, outline, workset, phaseCreated and designOption. level and heightOffset already exist and are not repeated. The outline is a list of closed loops of [x, y, z] built from the edges of the top faces. An edge found on two faces is inside the outline and is dropped, the rest is chained end to end, each loop closes from its last point back to its first, and a chain that does not close is left out and counted in one error line. Every part is read on its own, a failure is one error line per reason with the count and the first 5 element ids, and the floor keeps its other fields.
- **R53 Parameter details and floor types.** Floors, floor types and Revit links also have parameterDetails, a list of every parameter that holds a value, sorted by name, with name, builtIn (left out when the parameter is not built in), storage, text (the value as Revit shows it) and, for Double and Integer parameters, number with its unit (a length in m, an area in m2, a volume in m3, an angle in deg, any other number as Revit holds it with no unit). A name held twice keeps the later one as Name (2). Each detail is one line in the file. The document also has floorTypes, one entry for each floor type in use with typeId, name and parameterDetails. The old parameters key stays as it was.
- **R54 Link state.** A link entry also has elementId, status (the LinkedFileStatus of its link type), loaded, parameterDetails and, for a loaded link, boundingBoxCorners (8 points in shared coordinates) and transformShared (the link transform with its origin in shared coordinates). The corners come from the bounding box of the link instance when the API gives one, which is in host space, so no extra transform is applied. The API gives none when it does not know the model box, and the round 9 run gave none for 94 of 94 loaded links, because the geometry of a link lives in the link document. The corners then come from the extents of the loaded link document: the union of the bounding boxes of its model elements in link coordinates, leaving out view specific elements, elements with no model category, the base points and nested links and imports, with its 8 corners put through the link transform and the box around them taken in shared coordinates. The extents are measured once per link document. boxSource says api or linkExtents. From the link document only those bounding boxes are asked, the code that reads the link state never opens a file, nothing of the link document is written and the default of rule R39 stays. This is unproven until a run in Revit.

- **R94 Entry rule.** Measured from past work. The entry point of a ramp is the midpoint of its higher long edge, the long edges being those of R59 and the higher one the one with the larger mean level. A plot with no ramp gets the road level at its curb point plus a measured offset. The front edge of a plot is the edge of its plot face, not shorter than 1 m, whose midpoint is nearest to a road edge line of R71. tied says another edge is within 1 m of the nearest, which is a corner plot. The curb point is the point of that road edge line nearest to the midpoint of the front edge. The level is the lookup of R91 at the curb point plus the offset, with the surface that answered. A curb point no surface covers gives no level, which is listed and never filled in. The offset is the median of El @ Entry minus the road level at the curb point over the plots of the past job and lives in config/prototype_offsets.json under entry (R100), with the note measured from past work. python/entry_levels.py holds the rule and no value of it.
