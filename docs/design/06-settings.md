## 6. Settings

The user chooses every setting in the pane, nothing is read from or written to the registry (R106).

- What: Settings (the project settings file, config/project.json for this project), Rules (the rules profile, rules/roshn-makkah.json), Level profile (a name of levelProfiles of the rules file, levelProfiles.default when none is chosen, parsons2024Rev6, R277), the seven input files and folders, the scope and the dry run box, each a row of the mock. The override list and the work folder have no row in the mock, so they have none in the pane either: the config file the Settings row names holds them in its addin block, overrideFile (config/overrides/roshn-makkah.json, majority.overrideDefaultSources parsons applied, R330) and workFolder, and the tooltip of the Settings row shows both paths with the fit schedule of the location plan (section 5). So the pane matches the mock, and the user changes either by editing the config file.
- Where: one Extensible Storage entity on the ProjectInformation element of the document, schema SiteAdaptation_Settings (letters, digits and underscore only, as section 3 says of every schema name) with a fixed GUID, vendor SITEADAPT (the VendorId of the manifests), read access public, write access vendor, one string field SettingsJson holding the settings JSON of Common (R367, Common/Settings since 4h-1, the GUID in SettingsSchema). So the settings are saved with the .rvt, travel with it and come back when it opens. A new project starts with the defaults config names, prefilled from inputRoot and drawings of config (READ, config/project.json).
- The settings JSON: formatVersion, configFile, rulesFile, levelProfile, inputs (baseplan, villaBlocks, curbs, roadSurface, dlus, sales, plotNumbers, prototypes and parameterSheet, the parameter sheet Excel of the row Shared parameters of button 1 that Lane B 5a named (W10), each with its full path, size and SHA-256), scope (kind, nbh, plots), dryRunFirst, and per button its last run: time, mode, scope, the hash of every input, counts and issues. Paths are kept as chosen, the pane shows the file or folder name (7.2).
- When: a pick in the pane changes the settings in memory only. The Settings entity is written only inside the transaction of a real run of a button, with the record of that run, so a pick, a dry run and Cancel write nothing to the document and leave Document.IsModified as it was. Save setup of New project writes the entity at once in a transaction of its own (R445). The mock pane has no other save control, so the picks reach the file with the next real run or Save setup, and picks not yet written are lost when the document closes. A settings JSON of a later formatVersion is refused with both versions named.
- Work folder: by default `<work root>\<file name>_<path hash>`, the work root workRoot of %APPDATA%\SiteAdaptation\machine.json, else the SiteAdaptation folder of the Documents folder of the user (Environment.SpecialFolder.MyDocuments), by WorkRoot.cs (Q127, J8). A path of config/project.json or config/road_surfaces.json under the work root starts with {workRoot}, so no path of a user is in git (J5). The file name of Document.PathName without its extension, and the first 8 hex digits of the SHA-256 of that full path after Path.GetFullPath and in lower case, since Windows paths ignore case. So two .rvt files of one name in two folders never share a work folder, and Document.Title names none. Revit run 3 of Lane B 5a measured a document opened detached and never saved: its Title is "<central>_detached", not empty, and its PathName is "<central>_detached.rvt", a bare file name with no folder (RAN, steps/history/lane-b-2026-10-29.md, Revit run 3 of 5a). A document never saved has no PathName. So the add-in holds a PathName as saved only when it is a full path on a drive, X:\ or X:/, or on a share, \\server\share\..., and never one that holds "://" (SavedPath.Is in dotnet/SiteAdaptation.Common, R382). A bare name, a relative path, an empty path and a cloud or Revit Server path such as "BIM 360://..." or "Autodesk Docs://..." are not saved (CHOSEN in SavedPath.cs, since the work folder is named by a local file). A document whose PathName is not saved has no work folder: every button stops with "Save the project first, its work folder is named by its file" and the pane shows "not saved" and its steps with no status. So a cloud or Revit Server model gets the save first stop too, which does not help it, latent as no host model of this job is one. Never beside the .rvt and never beside the sources in C:\02-Site Adaptation. A workFolder of the config that lies inside inputRoot is refused, since the sources stay read only (R1). It holds the reads, plans, checks, run logs, the dry folders and the two Excel files of each NBH.
- Config gains in Phase 4a a block addin: overrideFile and workFolder (above), the position file (Q068, outside git), the file names of the config files beside it the build reads (floorOutlines floor_outlines.json, prototypeOffsets prototype_offsets.json, cadLayers cad_layers.json, roadSurfaces road_surfaces.json, areaCodes area_codes.json), the wall types, the shared parameter names with the GUIDs the keys hold (addin.sharedParameters, read from the key copies in Phase 4d, so a new site file and the keys share them, R353, replaced in R461 by the parameter sheet addin.parameterSheet names), the floor type thicknesses read from floorTypes of the key reads (R53, the Default Thickness of each type, Generic 150mm 0.10 m in the IMC key and 0.15 m in the IMD key, READ round_addin\logs\key_level_bases_pr49.txt), workerPeakMiB per input and workerTimeLimitS per command (R347), and the check point pass limit 1 mm, addin.position with the position file since Phase 4d (R353), and addin.plotTable, the decimals the overlaps of the blocks of a face are ordered at, since the review of PR 54 (R352). minFreeGB stays siteBuild.minFreeGB, the 2 GB floor of R200. No project value goes in code (CLAUDE.md).
