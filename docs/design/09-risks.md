### Open until a Revit run

What only a Revit run can settle, each with the phase that measures it. Until then each stays as this design says, and a result otherwise changes this design first (R343).

1. Phase 5a: the session id given on DocumentOpened and on a new document, the pane loaded again at ViewActivated, DocumentOpened and DocumentClosed, and a worker answer that ends while another document is active written to its own document, or dropped with its issue once that document closed (section 2, 7.2).
2. Phase 5a: Document.Title and Document.PathName of a detached document and of one never saved, and the stop that asks for a save first (section 6). Measured in Revit run 3 of Lane B 5a, not as this item first read it: a detached document never saved has the Title "<central>_detached" and the PathName "<central>_detached.rvt", a bare file name, and a document never saved has no PathName and asks for a save (RAN, steps/lane-b.md, Revit run 3). The add-in now holds a PathName as saved only when it is a full drive or UNC path and never one with "://" (SavedPath.Is in dotnet/SiteAdaptation.Common, R382), so a detached document and a cloud or Revit Server model stop with the save first stop (CHOSEN). The stop on a detached document is not yet seen in Revit (Q147). The two run checks "a detached document has no PathName" and "a detached document has an empty Title" measure the old claim and stay not held until they are changed or Q147 is answered.
