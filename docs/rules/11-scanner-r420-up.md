## Round 4j-1 rules of Lane D, the scanner of any CAD, Excel and PDF the user gives

The step audit of 31 Oct 2026 found the Plot and Villa type reads tied to ROSHN file names, layer names and codes. Bader's decisions of 31 Oct 2026: all plot data comes from the CAD files the user gives, and a scanner reads any CAD, Excel and PDF the user gives, finds where the villa type is and shows what it read. No file name, layer name or sheet name of a project is in the code. Every value is in the scan block of the rules profile, its rule in scan.ruleOf. The file shapes are in docs/design/17-scanner.md.

- **R420 CAD layer inventory.** Input: each CAD file the user gives, DWG or DXF. Every insert is exploded to its pieces as the Exploder of R19 explodes it, with no keep or drop list, so no layer is dropped. Output: one row per layer of the file, after the explode, with its closed outlines (the faces PlotShapes traces on the lines and arcs of that layer alone, a closed polyline among them), its texts, its block inserts and its line and arc segments, written to scan_cad_<n>.json with the file name, size and SHA-256. What the explode did not read, an external reference, a depth limit hit or a cycle, is a check row notRead, so no content is left out in silence. The second method is the face count of a polygonize of the same segments in python/scan_check.py, at the node tolerance and least area of the trace, and the face count of a button 2 read of the same layers is a third. The renamed proof set is made by the CadReader verb --rename-layers, which writes a DXF copy whose layers carry the names of a map, on copies in the work root only. Tests: R420_ScanTests.cs, test_scan.py, test_scan_check.py.
- **R421 Plot outline layer proposal.** Input: the faces of each layer alone and of each pair of layers that both hold at least scan.pairMinSegments segments (Q243), and every text of the same file that matches scan.labelPattern. A face covers a plot when exactly one such text lies inside it. Output: a score per candidate, the faces that cover a plot. The highest is proposed as the plot outlines of the file. A tie proposes none and writes a check row. The file with the highest proposal is the plot drawing, a tie makes none (Q244). A number that two plots of the plot drawing hold is a check row and joins no Excel or PDF row. A face of the proposed outline that holds two or more labels is a check row manyLabels, and a label in no face of it a check row labelOutside, so no plot is left out in silence. Tests: R420_ScanTests.cs, test_scan.py.
- **R422 Plot number layer proposal.** Input: the plots of the proposed outline of a file and the layer of the one label of each. Output: a score per text layer, the plots whose label lies on it, the highest proposed as the plot numbers, a tie proposes none. Tests: R420_ScanTests.cs, test_scan.py.
- **R423 Villa block layer proposal.** Input: the inserts of every file by layer and the plots of the plot drawing. Output: a score per insert layer, the plots that hold the insert point of at least one of its inserts, the highest proposed as the villa blocks, a tie proposes none. Tests: R420_ScanTests.cs, test_scan.py.
- **R424 Drawing link by plot.** Input: the plots of the plot drawing and of each other file with a proposed outline. Two plots link when the number is the same, the label text is the same and the centroid of each lies inside the other. Output: a conflict row with both values for a pair of the same number that does not link (field location or label) and for a plot of the other file whose centroid lies inside a plot of the plot drawing with another number (field number). The links themselves are not written, a link holds and only a conflict is shown. Never a silent pick. Tests: R420_ScanTests.cs, test_scan.py.
- **R425 Villa type value match.** Input: a block name, a text or a cell, the codes of the rules profile (the keys of typologies, their keo_file, the old and new codes of typology_codes) and the prototypes the user gives by file name, each name read to its code by prototypeNames of config. A value counts as a villa type only when the whole value equals one of those, or one of those lies in it as a run bounded by the start, the end or a character of scan.tokenSplit, the longest first and a matched run not used again, matched with case, so a code that holds a split character is kept whole. Output: the code as found, never renamed. A value that holds two codes is a check row, and a plot that holds such a value or two codes gives no villa type from that source. Tests: R420_ScanTests.cs, test_scan.py.
- **R426 Villa type source score.** Input: the block names inside each plot by file and insert layer, the texts inside each plot by file and text layer, every column of every sheet of every Excel file, every line of every page of every PDF file. An Excel sheet joins its rows to the plots by the column and the shift of scan.plotNumberShifts that match the most plot numbers, a cell number minus the shift being the CAD label, a tie joins none. A PDF code line pairs with its number line by the label pairs of R180, the number line whose top lies within scan.pdfPairDyPt under the top of the code line and whose centre lies within scan.pdfPairDxPt, the nearest first and one to one, the characters joined into words by scan.pdfJoinGapPt and into lines by scan.pdfLineTolerancePt. A pair joins when its number line holds one number token that matches a plot under the shift that matches the most plots of that file. Text on one line, as in a table, and turned text join nothing (Q252). Output: a score per source, the plots it gives a code read from a prototype file the user gives (Bader, 31 Oct 2026), a code of the profile alone found but not scored. The kinds are taken in order, block names inside plots first, then texts, then Excel, then PDF (Q254), and the lead is the source of the highest score of the first kind that scores, a tie there leaves no lead. The lead is proposed only when its share, its score over the plots that any source gives a prototype code, reaches majority.strongShare of config. Else no source is proposed, a check row noStrongSource names the lead and the best of each later kind with its share, and the user chooses in the scanner window. Every other source is listed as a check. A plot where a source gives another code than the lead source is a conflict row with both values, counted on the villaType rows of both sources, the conflicts of R424 on the plotOutline row, every other row 0. An old and a new code of one row of typology_codes are kept as found and make a check row, not a conflict (Q245). Tests: R420_ScanTests.cs, test_scan.py.
- **R427 Scan result file.** One scan result per run in the run folder, scan.json by the worker command scan and scan_python.json by python/scan.py, plain fields only: per row the source file, what was found, the proposed use, the score and the count of conflicts, then the conflict rows, the check rows and the plots with the villa type of each source, every list in the order of docs/design/17-scanner.md. The scanner window of Lane B shows it (steps/waiting-on-others.md). python/scan_check.py holds the two files equal field by field. Tests: R420_ScanTests.cs, test_scan.py, test_scan_check.py.
- **R428 Parallel pair trace.** Input: the layer pairs of R421 and scan.pairThreads of the rules profile (Q257). The pairs are traced on that many threads, each into its own place, so the candidates and the scan result are those of one thread, and the time of each stage and each pair goes to the worker log, never into the result. The trace of PlotShapes finds the crossings and the T junctions of a piece among the pieces and nodes in the cells along it, in the order a loop over every one takes, so a read of button 2 writes the same files (round 4j-1b, 21 of 21 by SHA-256 on the three ROSHN drawings). Tests: R420_ScanTests.cs.
- **R429 Scan time cap.** Input: scan.pairTimeCapS of the rules profile (Q258) and the clock of the pair trace of a file. Past the cap no layer pair is begun. Output: the pairs not traced listed under notTraced of scan_cad_<n>.json and one notRead entry "<file>|layer pairs" with "<n> of <m> not traced, time cap <s> s, listed under notTraced", so the scan result holds a check row notRead and nothing is left out in silence. A file that ends under the cap is the scan of R421. Tests: R420_ScanTests.cs, test_scan.py.
