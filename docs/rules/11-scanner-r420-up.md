## Round 4j-1 rules of Lane D, the scanner of any CAD, Excel and PDF the user gives

The step audit of 31 Oct 2026 found the Plot and Villa type reads tied to ROSHN file names, layer names and codes. Bader's decisions of 31 Oct 2026: all plot data comes from the CAD files the user gives, and a scanner reads any CAD, Excel and PDF the user gives, finds where the villa type is and shows what it read. No file name, layer name or sheet name of a project is in the code. Every value is in the scan block of the rules profile, its rule in scan.ruleOf. The file shapes are in docs/design/17-scanner.md.

- **R420 CAD layer inventory.** Input: each CAD file the user gives, DWG or DXF. Every insert is exploded to its pieces as the Exploder of R19 explodes it, with no keep or drop list, so no layer is dropped. Output: one row per layer of the file, after the explode, with its closed outlines (the faces PlotShapes traces on the lines and arcs of that layer alone, a closed polyline among them), its texts, its block inserts and its line and arc segments, written to scan_cad_<n>.json with the file name, size and SHA-256. The second method is the face count of a polygonize of the same segments in python/scan_check.py. Tests: R420_ScanTests.cs, test_scan.py.
- **R421 Plot outline layer proposal.** Input: the faces of each layer alone and of each pair of layers that both hold at least scan.pairMinSegments segments (Q240), and every text of the same file that matches scan.labelPattern. A face covers a plot when exactly one such text lies inside it. Output: a score per candidate, the faces that cover a plot. The highest is proposed as the plot outlines of the file. A tie proposes none and writes a check row. The file with the highest proposal is the plot drawing, a tie makes none (Q241). A number that two plots of the plot drawing hold is a check row and joins no Excel or PDF row. Tests: R420_ScanTests.cs, test_scan.py.
- **R422 Plot number layer proposal.** Input: the plots of the proposed outline of a file and the layer of the one label of each. Output: a score per text layer, the plots whose label lies on it, the highest proposed as the plot numbers, a tie proposes none. Tests: R420_ScanTests.cs, test_scan.py.
- **R423 Villa block layer proposal.** Input: the inserts of every file by layer and the plots of the plot drawing. Output: a score per insert layer, the plots that hold the insert point of at least one of its inserts, the highest proposed as the villa blocks, a tie proposes none. Tests: R420_ScanTests.cs, test_scan.py.
- **R424 Drawing link by plot.** Input: the plots of the plot drawing and of each other file with a proposed outline. Two plots link when the number is the same, the label text is the same and the centroid of each lies inside the other. Output: the links, and a conflict row with both values for a pair of the same number that does not link (field location or label) and for a plot of the other file whose centroid lies inside a plot of the plot drawing with another number (field number). Never a silent pick. Tests: R420_ScanTests.cs, test_scan.py.
- **R425 Villa type value match.** Input: a block name, a text or a cell, the codes of the rules profile (the keys of typologies, their keo_file, the old and new codes of typology_codes) and the prototypes the user gives by file name, each name read to its code by prototypeNames of config. A value counts as a villa type only when the whole value or one of its tokens, split by scan.tokenSplit, equals one of those, matched with case. Output: the code as found, never renamed. A plot or a value that holds two codes is a check row and gives no villa type. Tests: R420_ScanTests.cs, test_scan.py.
- **R426 Villa type source score.** Input: the block names inside each plot by file and insert layer, the texts inside each plot by file and text layer, every column of every sheet of every Excel file, every line of every page of every PDF file. An Excel sheet joins its rows to the plots by the column and the shift of scan.plotNumberShifts that match the most plot numbers, a cell number minus the shift being the CAD label, a tie joins none. A PDF line joins when it holds one number token that matches a plot under the shift that matches the most plots of that file, its characters joined into words by scan.pdfJoinGapPt and into lines by scan.pdfLineTolerancePt. Output: a score per source, the plots it gives a villa type, the highest proposed, the others listed as checks, a tie proposes none. A plot where a source gives another code than the proposed source is a conflict row with both values. An old and a new code of one row of typology_codes are kept as found and make a check row, not a conflict (Q242). Tests: R420_ScanTests.cs, test_scan.py.
- **R427 Scan result file.** One scan result per run in the run folder, scan.json by the worker command scan and scan_python.json by python/scan.py, plain fields only: per row the source file, what was found, the proposed use, the score and the count of conflicts, then the conflict rows, the check rows and the plots with the villa type of each source, every list in the order of docs/design/17-scanner.md. The scanner window of Lane B shows it (steps/waiting-on-others.md). python/scan_check.py holds the two files equal field by field. Tests: R420_ScanTests.cs, test_scan.py, test_scan_check.py.
