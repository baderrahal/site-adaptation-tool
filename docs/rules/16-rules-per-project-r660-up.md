## Round R2 C3 rules of build-2, the rules per project, no Revit call

Bader's order of the round: each project holds its own rule set beside its project profile, never in code. A shipped template is read only. A rule value has a source, computed, rule, person entered, default or missing, past only in past job mode, and a missing value is never guessed.

- **R660 Rules from a template.** Input: a request of the command rulesSetup with the roles template, projectFolder and config, and Who. The template is rules/templates/manual.json by choice of the person, past-job.json holds the past job measures and is never a default. Output: project_rules.json in the project folder with formatVersion, fromTemplate, beforeBuild warn and every template rule with status not confirmed, a rule with no value kept null with source missing and a mark, then the fixed rules of R663, and one line in rules_log.jsonl beside it. The run is refused with nothing written for no person, a project that already holds rules, a template with no rule, a repeated id or an id the tool keeps, a value whose source is not rule, default or past, no value with a source other than missing, a project folder inside the git work tree, an input root of config or a rules/templates folder. A template with a value tagged past is refused unless the request itself names projectRules.pastJobMode, the mode of config alone is not enough, and this goes by what the template holds and not its file name. Test: dotnet/SiteAdaptation.Tests/ProjectRules/RulesCommandTests.cs and RulesTemplateTests.cs, tests/acceptance/test_r2_build.py.
- **R661 One rule changed.** Input: a request of the command rulesChange with the roles rules and config, Who, RuleId and NewValue. Output: a new value sets source person entered, status confirmed, confirmedBy and confirmedWhen and takes off the mark. The value the rule already holds confirms it and keeps its source, whole and decimal forms of a number being the same value, since the request has no third field. A null value is refused, a value is never cleared. The runner does not mark this input as the command changes it, so the command itself refuses a file under rules/templates, any file not named project_rules.json and a file in the git work tree or an input root of config, each with nothing changed. Test: RulesCommandTests.cs, R640_WorkerSeamTests.cs, tests/acceptance/test_r2_build.py.
- **R662 Before Build setting.** Input: beforeBuild of project_rules.json and the status of each rule. Output: warn, the default and what an absent setting reads as, gives an issue naming how many of how many rules are not confirmed and the build goes on. Block gives BlockingLine. Any other word gives BlockingLine and never reads as warn. A rule with no value is never confirmed. rulesChange with the rule id beforeBuild changes the setting to warn or block alone, logged as any change. Test: RulesForBuildTests.cs, RulesCommandTests.cs, tests/acceptance/test_r2_build.py.
- **R663 Fixed rules and the log.** Input: the fixed rules fixed.saudiChecks, fixed.noGuessedValue and fixed.everyChangeLogged, which the tool holds and no template does, and every setup or change. Output: rulesChange refuses a fixed rule by its id, whatever the file says of it. RulesForBuild.Check says when the file changed or lost one and keeps it on. Each change adds a line with who, when in UTC, rule, old and new to rules_log.jsonl beside the rules, before the rules file changes, so a stop between the two leaves a line to look into and never an unlogged change. A write that fails adds a second line with failed and its reason. The log is held with no other writer for the whole change, a second run is refused. A request with no person changes nothing. Which checks the Saudi checks are is not defined in the repo, the rule holds the setting only. Test: RulesCommandTests.cs, RulesForBuildTests.cs, tests/acceptance/test_r2_build.py.
- **R664 Rules for a build.** Input: RulesForBuild.Check with the path of project_rules.json or null, and the config with projectRules.ruleNames and pastJobMode. Output: RulesChoiceLine, BlockingLine, Issues and Rules, each rule with Id, Name, Value, Source, Rule, Status and Marked. A null path gives the line that asks once, the choice of R660, and every rule of ruleNames missing and marked, never a past measure. A rules file not on disk or not usable gives BlockingLine in plain words and every rule missing. The file is not trusted on its word: no value, source missing, an unknown source or a past value outside past job mode each give a missing and marked rule, status confirmed with no person is not confirmed, and a rule the file lost is missing and takes nothing from a template. Test: RulesForBuildTests.cs, and through the build the tests R2-C2-build-1 holds in tests/acceptance/test_r2_build.py.
