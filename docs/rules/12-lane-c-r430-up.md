## Lane C rules, the windows New project, What the tool read and the step gates

Lane C NEWPROJ-UI (PR 112, 31 Oct 2026) and SCAN-UI (1 Nov 2026). The ids R430 to R449 are Lane C's. The design is docs/design/18-new-project.md, the boards are in docs/design/boards. Every rule here sets what a window shows or saves, none sets a value of the plan.

- **R430 Five setup rows of New project.** Input: none, the rows are fixed. Output: the rows site, plot list, villa levels, road levels and parameter sheet, each with the inputs of the settings JSON it fills (baseplan, sales, none, roadSurface as an optional folder, parameterSheet), the buttons it serves and its template. Common/Settings/SetupRows.cs. Tests: R430_SetupTests.cs.
- **R431 Read only setup check.** Input: the settings of the project and a test of whether a path is on disk. Output: per row found, missing or later, whether config is named and on disk, the stops of the buttons and Ready, nothing written. Common/Settings/SetupCheck.cs. Tests: R430_SetupTests.cs.
- **R432 Save setup in R367 format.** Input: the draft of the window, the saved project chosen and the path picked per input. Output: the settings of R367 with the draft laid over them, read back through SettingsJson, the dry run tick and a held parameter sheet kept, the settings given unchanged, nothing written to a model. Common/Settings/SetupSave.cs. Tests: R430_SetupTests.cs.
- **R433 Template workbook of a row.** Input: the row and config. Output: the sheets of the template, the parameter sheet with its columns or the data book sheets by addin.workbookRoles, written as a new xlsx, never into an input folder and never over a file. Common/Settings/TemplateBook.cs. Tests: R433_TemplateBookTests.cs.
- **R434 Saved projects of the work root.** Input: the work root. Output: the folder Saved projects under it and the saved projects in it by name, a file that does not read left out and listed. Common/Settings/SavedStarts.cs. Tests: R430_SetupTests.cs.
- **R435 Scan value status.** Input: the text of scan.json (R427) and the saved scanPicks and conflictPicks of the settings. Output: one row for each of plot outline and villa type, and of plot number and villa block when they have a row of their kind, its sources in file order, the proposed source (the row whose proposedUse is neither empty nor check), the selected source (the saved pick when it names a source of the row, none when it names no source of this scan, so a renamed file asks again, else the proposed), Covers, Checks and the Status, Clear when a source is selected, else Pick with a line on what the best source covers. One row for each file of inputs but the settings file of role config, with what it found, Read or Not read when a check notRead names it. One row for each conflict with its two choices, the selected one (the saved pick when it is sourceA or sourceB, else sourceA) and Open when no pick naming one of its sources is saved under its key "<plot>|<field>|<sourceB>", since the scanner writes one conflict per other source of a plot and field. NeedsWindow is true when a value is Pick or a conflict is Open. Common/Scan/ScanView.cs. Tests: R435_ScanViewTests.cs, ScanResultsTests.cs.
- **R436 Save scan picks with setup.** Input: the picks of the window and the settings. Output: the settings with the picks laid over scanPicks and conflictPicks, the value rows the user changed and every conflict with the choice it shows, Use the proposed for all leaving a conflict already picked as it is, the settings given unchanged, read back through SettingsJson, so they are saved with the setup in the settings JSON of R367, whose formatVersion stays 1 with the new fields null in an older file (Q288). Export writes the sheets Values, Files and Conflicts as the window shows them to a new xlsx and refuses a path that exists. Nothing is written to a model. Common/Scan/ScanPicks.cs. Tests: R435_ScanViewTests.cs.
- **R438 Button 2 scan gate.** Input: the drawings, schedules and plot numbers of the pane by their extension (CAD, Excel or PDF), the prototype files of the Prototypes folder and the Settings file as config, curbs and road surface left out while the Road Layout scan takes over 40 minutes (Q250). Output: the worker command scan of R427 into scan_<run id> of the work folder before the read of button 2, then the gate: every value Clear and no conflict Open gives the pane line "Read <n> files, <n> plots, every value clear." and the read goes on, else the window What the tool read opens, Use these picks lays the picks into the settings of the pane and the read goes on, Cancel stops the read with nothing written. A scan that fails or times out lets the read go on with its reason. A run of the test host (SITEADAPT_JOB set) reads with no scan. Common/ReadData/ScanStep.cs Wrap, AddIn/ScanResults/ScanGate.cs Ask, called by ReadDataBody.For from Buttons. Tests: R438_ScanStepTests.cs, ScanGateTests.cs.
- **R439 Scan reuse by input hash.** Input: the scan inputs of a press of button 2 and the scan_ folders of the work folder. Output: the scan.json of the newest folder whose inputs hold the same files by name, size and SHA-256, so no scan runs again on files that did not change, else none. A scan older than the rules profile or the worker of the add-in is not reused. A hash is kept per path, size and write time for the session, so the prototypes are not hashed again on each press. Common/ReadData/ScanStep.cs Latest and Reusable. Tests: R438_ScanStepTests.cs.
- **R440 Drawing facts from the scan.** Input: the latest scan.json of the work folder, else the latest read of button 2. Output: the layers of the plot drawing, the plots, the villa types and the proposed plot layer for the block What the tool read from the drawing of New project, the plot outline sources as the layer dropdown, the Excel villa type sources as the sheet and column dropdowns, one grey line for the survey point the scan does not read, View opening What the tool read, and Save setup laying the picks the user changed into scanPicks and the conflict picks of the window into conflictPicks. Common/Scan/ScanFacts.cs, LatestScanFacts of AddIn/NewProject/DrawingFacts.cs, the default of NewProjectDialog.Facts. Tests: R440_ScanFactsTests.cs, NewProjectTests.cs.
- **R441 Current files gate.** Input: the settings of the project and the rules profiles in the folder of the rules file, else in rules beside the folder of config. Output: one row per file of the setup but the prototypes folder with its tick Current, saved as "<input>|<file name>" so a new file of the input is not ticked, the site drawing marked, a line when the setup holds no site drawing, the profiles by the name each gives itself, Apply of 1 Set up site grey until the site drawing is ticked, the ticks and the rules file laid into the settings on Apply only, and the line "Current files: <files>" after the lines of button 9. A stand-in window that gives no ticks keeps the ticks the settings hold. Common/SetUp/CurrentFiles.cs, CurrentFilesDialog called by SetUpSiteBody, WithReportLine called by ReportBody. Tests: R441_CurrentFilesTests.cs, SetUpSiteTests.cs.
- **R442 Cluster confirm marks.** Input: the plan of NBH the last done 4 Check wrote, found by VillaLoad.LastPlan and held against the SHA-256 its check.json names, its proposal per plot of R411, and the cluster confirm review_<NBH>.json keeps. Output: per plot the proposal shown "<cluster> mirror <yes|no|none>", the plots of the cluster joined by +, or "No proposal" for a reason with no cluster, its reason as tooltip, and the plot table cluster with no proposal, a tick Confirmed live only on a plot with a proposal, Confirm all proposed ticking every plot with one and grey with none left, and on Save review the fields clusterConfirmed, clusterUnconfirmed and clusterPlanSha256 of review_<NBH>.json. clusterUnconfirmed is the list buttons 5 to 8 read to skip a plot with the reason "cluster not confirmed in 3 Review data". A confirm holds only against the plan it was made on, with no plan the saved fields stay as they were, and with no plan of 4 Check or a plan of the past job there is nothing to confirm and no plot is marked. A file of before R442 reads as none confirmed and none to skip. Common/Review/ClusterConfirm.cs called by ReviewLoad.Load and ReviewDataRun.Show, ReviewFile.Write and ReadClusters, the column and button of AddIn/ReviewData/ReviewDataWindow.xaml. Tests: R442_ClusterConfirmTests.cs, ReviewDataTests.cs. Buttons 5 to 8 skip the plots of clusterUnconfirmed once Lane B joins them (steps/waiting-on-others.md, Q296), the window marks them only.
- **R443 Door level source counts.** Input: designBasis.doorLevel of config, its source and civilFile.path, a relative path taken from the folder above the folder of config as addin.overrideFile is, the step levels of the run of 4 Check with doorSource per plot (R408) and DoorLevelSource of the settings, civilFile or roadPlusSlope, null until a pick and any other value refused by name. Output: the row Door level from of the window of 4 Check with the two choices "Civil entry file (<n> plots)" and "Road level plus slope (<n> plots)", each the plots of the step whose doorSource is that source, 0 when the run wrote no step levels or ran the past job, the civil choice grey with the one help line "No civil entry file in the setup, so the door level comes from road level plus slope." when config names no civil file or the file is not on disk, the selected choice the settings pick, else the source of config, else road level plus slope, as a grey choice is never selected, no row when config holds no designBasis.doorLevel, and a pick kept in DoorLevelSource of the pane settings at once, written to the model with the record of the next real run (R367). The build of 4 Check still takes designBasis.doorLevel.source of config, the pick waits for Lane A. Common/CheckTable/DoorLevelPick.cs and DoorLevelText.cs, DoorLevelSources and DoorLevelSource of Common/Settings/ProjectSettings.cs, DoorLevelPick.Of called by CheckRun.Answered, CheckRun.DoorPick and DoorPicked set by CheckTableBody.DoorWired called by CheckTableBody.For, CheckTableCallbacks.DoorLevel taken by CheckTableViewModel.DoorSource and CheckTableSession.PickDoorLevel. Tests: R443_DoorLevelPickTests.cs, the R443 tests of CheckTableTests.cs and R376_CheckRunTests.cs.
