## Lane C rules, the windows New project, What the tool read and the step gates

Lane C NEWPROJ-UI (PR 112, 31 Oct 2026) and SCAN-UI (1 Nov 2026). The ids R430 to R449 are Lane C's. The design is docs/design/18-new-project.md, the boards are in docs/design/boards. Every rule here sets what a window shows or saves, none sets a value of the plan.

- **R430 Five setup rows of New project.** Input: none, the rows are fixed. Output: the rows site, plot list, villa levels, road levels and parameter sheet, each with the inputs of the settings JSON it fills (baseplan, sales, none, roadSurface as an optional folder, parameterSheet), the buttons it serves and its template. Common/Settings/SetupRows.cs. Tests: R430_SetupTests.cs.

Common/Settings/SetupSave.cs. Tests: R430_SetupTests.cs.

One row for each file of inputs but the settings file of role config, with what it found, Read or Not read when a check notRead names it. One row for each conflict with its two choices, the selected one (the saved pick when it is sourceA or sourceB, else sourceA) and Open when no pick naming one of its sources is saved under its key "<plot>|<field>|<sourceB>", since the scanner writes one conflict per other source of a plot and field. - **R449 Two Revit window slots.** Input: siteBuild.revitSlots, revitSlotsMinTotalGB and maxWindows of config/project.json, the physical memory of the machine, the slot files, the window processes and free memory. Output: on a machine of at least revitSlotsMinTotalGB, 65,221 MB on this laptop on 2 Nov 2026, Lock of python/window_lock.py holds revitSlots slots, 2, slot 1 is the lock file of R200 and slot 2 window-2.lock. - **R447 Run timing per step.** Input: one run of a button through Buttons.Run, a clock, the calls of the Revit side that report (Commit, start and roll back of RevitTransaction and the Commit of a mass file as transactions, the preprocessor of WarningCollector as warnings, each Regenerate as modelRefresh, the save of a mass file as saving, the waits of ReportWorkerClient and UpdateWorkerClient as workerWait) and from a caller through RunTiming.BeforeRun the seconds of revitStart and modelOpen, the project made from the template and its save counted in modelOpen, null where nothing measured them, held for the next run that writes so a job counts one open once. A step is a phase of the flow, start, prepare, hashes, preview, confirm, hashesAgain, workerStart, worker, workerEnd, window, outside, apply, readBack, commit, outputs and outsideEnd, and worker and window may come again in a run. A measure takes its time out of what it sits in, so the categories and other of each step add up to its total in whole milliseconds, and the steps to the run. What nothing measured says the word absent, never 0. Seconds and counts only, no coordinate or level. A stop before the run id writes nothing. A failure of the clock or a write leaves the timing short and changes no outcome, plan, model or count. No Revit type, Common/Flow/RunTiming.cs. Tests: R447_RunTimingTests.cs.
