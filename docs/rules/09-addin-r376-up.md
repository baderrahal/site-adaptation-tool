
## Round ADDIN rules from R376, Lane B 5c

- **R376 Button 4 Check, the check table, Use and Save overrides.** CheckRun of Common/CheckTable is button 4 as a body of the flow of R382 with no model element, so no transaction opens, and the flow stops before it while step 3 is not done (R366). It takes the latest read of button 2 in the work folder, the read.json of the largest run id, and gives the worker command build every step from faces to checkRows and summary on the NBH of the scope, or the whole project, with the inputs by role: config, plotsCsv, labels and each roadSurface of the read record, baseplanRead, villaBlocksRead, curbsRead and workbooksRead from the read folder, the rules profile of the Rules row or config profile, the override list of addin.overrideFile or else the list of the rules profile by its name in overrides beside config (CHOSEN by Code), and prototype:<file name> for each prototype file of the Prototypes row. It stops before any start, each stop named: no read of step 2, step 2 done on other inputs, a read output missing, the rules file or the override list missing, no prototype file, floor_outlines.json or prototype_offsets.json not beside config, no site.json of button 1, a level profile the rules file does not hold (R277) and an override list PlanOverrides.Load refuses (R280). The end of the build writes checks_<NBH>.json, checks_all.json for the whole project, the rows of the check table: those of the step checkRows of R363, a plot marked Wrong in 3 Review data with check type Team check (CHOSEN by Code), and with the past job of Q117, key_join.json and the key reads testhost_<job>_prototypes.json, both optional, the Plot cut rows of every key plot whose join status is not joined and the Unit code rows of a key link whose file names another unit than Typology_Rev9 of the plot. Past of a row of no override takes the hand or the text of a parameter from the link of the key that holds the plot. With no past job Plot cut shows no rows and one line says so. Rows follow the check types of checkRows.types, then any other type by name, and each names its manual rule id by a lookup of check type and field, none until it is wired. Each row opens on Past when the build applied an override for it, else Rule. Past is grey with its reason where the 03b table offers none, on a row of no override no answer key holds, "no answer key holds plot [n]", and where the past job gives no value. Save overrides writes only the rows whose Use differs from the opening value, each with "byHand": true: Rule on an override marks "use": "rule", Past on one the build left "use": "past", Past on a row of no override adds the entry with the key and model of the answer key and the group of majority.groups that holds the key as source, and Skip adds {"plot", "reason", "byHand": true} to the list skip. Every line no change touches is kept byte for byte in the one entry per line form of majority.overrides_text, a list of another form is refused, the text is checked by PlanOverrides.CheckEntries and CheckSkip and written by a temporary name and a rename, then the plan is built again. A dry run builds into dry\<run id> and shows the table with Save overrides greyed. ICheckTableDialog is the seam of the window.
