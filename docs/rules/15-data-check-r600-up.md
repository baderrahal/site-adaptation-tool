## Round R1 rules of build-1, stage 1 Project data from the raw files of a folder

Bader's order of the round: stage 1 runs on a folder as a team hands it over, with no past file, no schedule of a past job and no name given. The worker command dataCheck builds on the scanner of R420 to R427 and reads no rules profile, every value it needs is in the dataCheck block of config/project.json with its why beside it. A value copied from the past job says so there and is no choice of this command. A value the block lacks is a plain line in the data check, never a default of the code. Files: dotnet/SiteAdaptation.Common/DataCheck/, dotnet/CadReader/DataCheckCommand.cs.

- **R600 Data check command.** Input: a request of the command dataCheck with the role scanFolder, a folder, the role config and an output folder, each with an empty SHA-256 allowed for these two roles of this command alone. The folder is walked in ordinal order, no link or junction followed, and each drawing, workbook, PDF file, surface file, rule set file, shared parameter file and the names of the prototype files are found. Output: data_check.json with one row of mark and one plain line for each of the 11 needs, a value for the mirror, the files read or not read and the ties, project_profile.json and plots.json in the output folder, and every file the command opened in answer.opened with its name, size, write time and SHA-256 before and after, a change ending the run with exit 4. Another older command and another role still refuse an empty SHA-256, siteBuild, rulesSetup and rulesChange take one on their own files (R640_WorkerSeamTests). Test: R600_DataCheckTests.cs, tests/acceptance/test_r1_stage1.py.
- **R601 Groups by distance.** Input: the outlines of the plots of the plot drawing and dataCheck.groupGapsM, one distance in metres for each group level, the largest group first, turned into the unit the drawing states. Output: for each level the groups of plots whose outlines lie within the distance of each other, a chain of such plots one group, no name of a layer, text or block used. A drawing that states no unit is taken as metres and says so, and the groups are then weak. A unit the table does not hold gives no group at all, the plots carry an empty list of groups and the reason. An outline with no number that lies inside no plot and is no larger than dataCheck.standInMaxArea times the median plot gets no row and stays in the distance test, so the gap of a plot with no number reads as no road. Two candidate outlines that tie on the plots they cover, one the other with more layers, are broken to the one with the fewest layers and the tie is said under ties. Any other tie leaves no proposal and the line names it. Test: R600_DataCheckTests.cs, test_groups_are_found_by_shape.
- **R602 Plots with no past file.** Input: the proposed plot outlines, number layer, villa block layer and villa type source of the scan, and the prototype file names read to a code by dataCheck.prototypeFilePattern. Output: for each plot its number, the villa type, the mirror of the villa block inside it and its groups, each value with a source tag computed or missing, and a reason for each value missing. A block is placed on the plot that holds the centre of what it draws and belongs to the smallest outline that holds it. The villa type of a plot is the one code the first kind of source that gives it agrees on, blocks, texts, a sheet column, a PDF page. A plot another kind of source contradicts is counted as disputed with the reason in plots.json, and the need is weak when more than 1 less strongShare of the typed plots are disputed or when a sheet holds villa type codes for many plots and joins few of them. A plot with a label of two numbers is written with number null, source missing and the reason naming both numbers, never the last, and the sheet and page sources, which join by number, are not used for it. Every line of a need follows the drawing the scan chose to give the plots, never the first drawing that has a proposal. A plot with a hole is flagged and what lies in the hole is left out of its mirror. The mirror is the sign of the block scale, a weak value on every plot because the folder does not say which hand a prototype file has. No schedule, plots.csv, labels.csv, border, override list or key is read (steps/truth-audit.md items 1, 2 and 7). Test: R600_DataCheckTests.cs, test_plots_are_read_with_no_past_file.
- **R603 Group level words.** Input: the group levels of R601, the texts of the plot drawing outside every plot and within dataCheck.wordReachM of one, and the headers of every sheet that joins to the plots by number. Output: the project's own word for a level. A header whose values part the plots as the groups do is enough alone. A word of the drawing alone needs dataCheck.wordMinGroups groups and a share of dataCheck.wordShare of the groups of the level. Two words that both qualify, or two headers, leave the level with word null, source missing, the candidates and the reason named in project_profile.json and in the line. A level with none has word null and source missing, never a guess. Test: R600_DataCheckTests.cs, test_the_profile_takes_the_projects_own_words.
- **R604 Road edge layer.** Input: the lines of each layer of the plot drawing that is no plot outline layer, with at least dataCheck.roadMinSegments lines, dataCheck.roadOutsideShare of them outside the plots, and dataCheck.roadReachM. Output: the layer with a line within the reach of the most plots and the share of the plots it reaches. Reach alone proves no road, so the mark is at most usable and the line says not scored. Test: R600_DataCheckTests.cs, R604_road_edges.
- **R605 Marks and plain lines.** Input: the counts of R600 to R604 and dataCheck.strongShare and usableShare. Output: for each need the mark strong, usable, weak or missing and one line in CAD and Revit words, at most 160 characters, with no bracket, no code word and no name of a layer that looks like code. A mark never rises as the data gets worse, a need takes the worst mark its facts give. Outlines with no number or two numbers, numbers outside every outline and a number used twice are said in counts, a share never passes 100 percent and a repeated number makes the plot numbers weak. Land XML surface files give road levels usable, a coordinate system stated in one gives coordinates usable, rule set and shared parameter files given usable, nothing found missing. Test: R600_DataCheckTests.cs, test_every_need_has_a_mark_and_one_plain_line.
- **R606 Files that fail.** Input: a file that fails to read, is held open by another program or is refused by the memory check, which holds a drawing to its size times the number of its file type in dataCheck.drawingPeak, dwg or dxf, and the floor siteBuild.minFreeGB. Output: a row in data_check.json files with its exact error, the run carries on with the other files and ends with exit 0, an empty folder gives every need missing with a line, and the check never swaps in a dummy file. Test: R600_DataCheckTests.cs, test_a_broken_drawing_is_said_and_the_run_carries_on.
- **R607 Scenario scoring.** Input: the five scenario folders under the work root and the right answer of each, the manifest of each folder before and after, and built_from.json in each run folder with the commit of the worker. Output: scripts/scenarios/run_stage1.py runs stage 1 on each folder in place, scripts/scenarios/score_scenarios.py writes steps/scenarios.md with counts and marks only, scripts/scenarios/second_check.py counts the plots of the sheet by neighbourhood and villa type by another route and shows the under read and over read. run_stage1.py --confirmed runs each scenario again into runs/<name>_confirmed on what its own first run proposed, by scripts/scenarios/confirmed_profile.py, the codes, column, guesses and words of the tool and nothing from a past file or an answer, and steps/scenarios.md holds both tables. second_check.py --confirmed counts the villa types per neighbourhood against plots.json. Test: R600_DataCheckTests.cs, R607_the_scores_table, tests/acceptance/test_r1_stage1.py, scripts/checks/test_scenarios.py.
- **R608 Clean folder build.** Input: samples/new-project, the made up project of tests/acceptance/made_up_project.py, and build.json naming scripts/scenarios/clean_stage1.py. Output: the build reads the sample and runs stage 1 on it through the worker, it fails when the worker opened a path of scripts/checks/past_paths.txt, read no plot or changed a file of the sample. Test: R600_DataCheckTests.cs, R608_the_sample_project, scripts/checks/clean_folder.py.
- **R620 Data check in the window.** Input: the input folder of the settings, addin.workerTimeLimitS.dataCheck, and the answer of the worker command dataCheck (R600) to the launch of the scan of R438. Output: button 2 starts the check by that launch and the pane waits on its run, Revit never waits (R347). Its rows, one per need with its plain name, its mark and its line, the files not read with the exact reason of data_check.json and the note of a check that stopped, go in the section Data check of the window What the tool read, in the one window with the values of the scan when the read goes on, alone with a Close when the read cannot go on. The files read and the plots found of that window come from data_check.json and plots.json of the run, and the sections of the scan, its picks, its conflict count, Export and the badge of step 3 are not shown when the check is alone. A folder with no input folder named or not there, a worker that cannot start, a time limit, a result file missing or unreadable or with no needs each stop the press and say why in plain words, the read never goes on as if the check had read. A run does not start while a check or a scan of the same work folder runs. Layout CHOSEN by Lead, docs/design/12-ui-spec.md holds nothing for it. Test: R620_DataCheckWindowTests.cs.

## Round R2 C1 rules of build-1, the gaps of stage 1 that block a correct build

Bader's order of the round: the villa type code map, the hand of each prototype and the group words are project inputs, found by what the handed over files hold and confirmed by a person, never copied from a past file. Nothing here reads a sheet or column by its name.

- **R630 Code table.** Input: every sheet of the workbooks of the folder that lists no plots, the prototype codes, dataCheck.codePattern, dataCheck.codeTableMaxPairs, strongShare and usableShare. Output: in project_profile.json codeMap.proposed, each row old, new and source computed, codeMap.foundIn and every other table under candidates. A table is two columns side by side whose cells both have the shape of a code, at least two pairs, one that renames, a pair repeated on under 1 less strongShare of its rows, at most codeTableMaxPairs pairs and one side holding usableShare of the prototype codes. A row with one code is skipped, and a first row that holds codes counts as a row. Only the renames tell the direction, by no word of a header: the side whose base codes the drawings use more is the old one, with no difference there the side the prototype files name more is the new one, and with neither it is read left to right and the line says it is a guess. A table whose old side the drawings hold nothing of is said unsure and comes after the others, as a room schedule or a price list of two code columns does. A code both old and new, a chain or a swap, is named under bothOldAndNew and weak, on a proposal as on a confirmed map. Past codeTableMaxPairs a table is found and said too large under tooLarge, never proposed. Best first by a sure table, prototype codes covered, renames, pairs, then the order of the files. No prototype codes or no such table gives an empty list, source missing and a line that says it. A proposal changes no plot. Test: R630_StageOneGapsTests.cs, test_a_table_of_old_to_new_codes_is_found_by_what_it_holds, test_no_table_says_so_and_lets_the_user_type_it.
- **R631 Typology column.** Input: the columns of each sheet that lists usableShare of the plots by number, and the groups of R601. Output: typologyColumn.proposed with workbook, sheet, column, plots and prototypePlots, null when there is none, and the rest under candidates. A column qualifies when a cell of code shape is given for usableShare of the plots, it holds two codes or more, as one value on every row says nothing of a plot, strongShare of its coded plots hold a code found in two groups or more of the finest level, as a type runs across groups and a block name does not, and under strongShare of them repeat the code the drawing gives, as a copy of the drawing settles nothing. A name two columns of one sheet carry is neither proposed nor taken. Past codeTableMaxPairs codes a column is found and said too large under tooLarge. Best first by plots whose whole cell is a prototype code, then the share of the rows of the column so filled. Columns of one rank that give some plot another code are a tie: the line says so and none is proposed, the person picks, a column never wins by coming later. Columns of one rank that hold the same code on every plot are one answer, the first in reading order is proposed and tie says so. Test: R630_StageOneGapsTests.cs, test_a_typology_column_per_plot_is_proposed.
- **R632 What a person confirmed.** Input: the optional role projectProfile, a file with codeMap, hands, levels and typologyColumn, which may carry an empty SHA-256 for dataCheck and for the commands siteBuild, rulesSetup and rulesChange. Output: a value of the wrong shape or an unreadable file refuses the run with its reason, so a run that goes on honoured all of it. A confirmed column gives each plot its code, a plot it does not list or lists with no code has none and says why, what the drawing said is not kept for it, a plot whose label holds two numbers keeps what the drawing gives. A confirmed column of one value, one gone from the folder, one whose name two columns carry or one that does not join changes no plot, and the reason leads the need line, which is then weak. Each plot where the drawing gives another code than the column keeps that under disputed and the need line counts them, the mark does not fall for them as a person settled it. A plot listed twice is counted, with two values it is weak. The confirmed map then turns the code once: a code it does not rename stands, a code both old and new or one that would land on such a code keeps what was read, weak and named, and one old code with two new codes, itself among them or not, is no pick and is weak with both named. An old code no prototype holds is looked for in the drawing and the sheets too, and a map entry or a hand naming a code no plot holds is listed under notHeld and said. Each confirmed block carries source person entered and each plot value worked out from it computed, the code as read stays in codeRead. A plot typed with no prototype file is weak and names the code, the need is then weak, as for a zone column taken for a villa type. Test: R630_StageOneGapsTests.cs, test_a_confirmed_map_gives_the_new_code_with_its_source, test_a_proposed_map_changes_no_plot_until_it_is_confirmed.
- **R633 Prototype hand and mirror.** Input: the inserts of the villa block layers inside the plots, the code each block name holds, dataCheck.handGuessShare, and the confirmed hands. Output: hands.proposed for each prototype code, right when its blocks are drawn unmirrored on handGuessShare of the plots that hold one, left when mirrored, null otherwise or with no block, with hands.evidence and hands.proposedAs saying it is a guess, no prototype file being opened. The mirror of a plot is the sign of the block scale, turned over when the confirmed hand of its code is left. It stays weak with no confirmed hand, and with one when the block in the plot is not of the plot's own type. A guess changes no mirror until it is confirmed. hands.source is computed only when a guess is there, missing when each is null. Test: R630_StageOneGapsTests.cs, test_mirror_follows_the_block_scale_and_the_confirmed_hand, test_a_hand_is_proposed_per_prototype_and_shown_as_a_guess.
- **R634 Words from a naming text.** Input: the texts and headers of R603, dataCheck.groupNamePattern and wordShare, and the confirmed levels. Output: a text counts for a word only when its last token matches groupNamePattern, as a group name does and the last word of a note or a building does not. A header counts only when its values name two groups or more and wordShare of the groups of the level, so one value over one big group and a lone plot names nothing. With none the level has word null, source missing and the line asks to name it once, a level the person named takes that word with source person entered. Test: R630_StageOneGapsTests.cs, test_a_group_word_comes_only_from_a_text_that_names_groups, test_a_level_the_user_names_is_taken_with_its_source.
- **R635 Read data on a raw folder.** Input: the settings file of button 2, the project mode, addin.readData and dataCheck of config. Output: ReadInputs.NoPastFiles is true for a rev6 project whose input root is on disk and which lacks a schedule or data book file of the old read. ReadDataRun then starts the worker command dataCheck on that folder with config and the confirmed profile of the work folder when it is there, into the read folder named by a hash of the name, size and write time of the files, with no read step, no pick and no stop for a schedule, border, plots.csv or labels.csv, and its preview names the folder by its whole path. A folder named in dataCheck.skipFolders is not walked at any depth, a list of the past output folders of the job, empty allowed, as the tool cannot judge a file by its name, and is listed under skippedFolders. data_check.json names under proposalSources each sheet a proposal came from. Areas: every later button works per area. A column of a sheet that lists the plots is proposed under areaColumn when it gives usableShare of the plots a value, holds two values or more and fewer than the blocks of the finest level, one value runs across blocks, and the plots around a plot, dataCheck.areaNearPlots at most and a quarter of the plots, agree with its value by dataCheck.areaAgreement beyond chance. Best first by the most areas then the most plots, a tie that parts plots otherwise proposes none. A proposal changes no plot. With a column confirmed each plot carries it under area, with source person entered, the header is the word of level 1 unless the person typed one, and a plot it does not list has none and says why. With none the groups of level 1 stand, the line of groupLevels says the areas were found by distance only and how many and to pick the column. A confirmed area column gone or of one value changes nothing and makes the need weak with the reason. dataCheck writes read_plotTable.json from plots.json, one row per numbered plot with its source tags, so 3 Review data and the scope read it as any read. Past job mode and a project that holds every past file keep the old read and its stops. Test: R630_StageOneGapsTests.cs, R635_a_raw_folder_reads_through_the_call_of_the_add_in_and_review_data_follows, R635_a_column_that_parts_the_plots_on_the_ground_is_proposed_under_any_name_and_changes_no_plot, R635_past_job_mode_keeps_the_old_read_and_its_stop.
- **R636 The window Confirm what was found.** Input: data_check.json and project_profile.json of the read folder of a read of R635, confirmed_profile.json of the work folder when it is there, dataCheck.groupGapsM of config. Output: after a read that ended done the check shows in the window What the tool read, then the window Confirm what was found opens, the smallest version CHOSEN by Lead as no sketch covers it. A column starts on the one confirmed before, else the one proposed, else none, the code map on the pairs confirmed before, else proposed, one pair per line as old -> new, and it says beside the map when its direction is only a guess or the table is unsure. A press on Confirm writes both columns and the code map as they stand, also when untouched, as a person confirming what the window shows, CHOSEN by Lead, so the read tags them person entered. A hand guess is shown beside an empty box and goes in only when a hand is picked, as R633 says a guess changes no mirror until it is confirmed. A level word goes in only when typed, changed or confirmed before, a computed word left alone stays computed and does not go over the header of a confirmed area column, both CHOSEN by Lead. A line that is no pair or a code that starts or ends with a character of the arrow is refused with its line number and writes nothing. Every block empty writes nothing and removes the file of an earlier Confirm. Cancel or the X saves nothing and is no failure, the read stays done. A check that stopped opens no confirm window and fails in plain words. A confirmed file the worker would refuse stops the press before any worker with the Apply or Cancel prompt of the flow: Apply removes it and says to press again, as the flow hashed it before its dry run, Cancel keeps it and the read does not run. On such a project button 2 has the inputs Settings, the input folder by the list of its files and the confirmed file when it is there, so a changed file of either leaves step 2 not done, past job mode keeps the inputs of the pane and the old body. Test: R636_ConfirmWindowTests.cs, The_raw_branch_through_For_runs_one_check_with_no_scan_then_the_two_windows, A_press_on_Confirm_takes_both_columns_and_the_code_map_as_the_window_shows_them, A_hand_guess_is_shown_and_does_not_start_selected_so_a_press_writes_no_hand, A_computed_level_word_left_alone_is_not_written_a_typed_one_is, Clearing_every_block_removes_the_file_of_an_earlier_confirm_and_says_so, A_confirmed_file_the_worker_would_refuse_asks_and_a_yes_discards_it_with_no_worker.
- **R639 Stage 1 says what it did.** Input: data_check.json of the read folder of a read of R635, the old read's list in addin.readData of config, the column names of a sheet, missing of read_plotTable.json. Output: a raw read whose check stopped or left a file or folder not read is never reused, and its confirm and end lines say why it reads again.
