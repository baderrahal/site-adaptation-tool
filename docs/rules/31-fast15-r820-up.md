Bader's order of 8 Nov 06:45, item 3. F22 still stood in run 2 of 01A: Confirm could not apply, the gathered file of the read was 1,033 MB, over the 1,000 MB limit of R792, so the demo needed a second read of about 12 minutes. Ids R820 to R829, R820 to R823 used.

- **R820 Confirm checks in the worker.** Input: the read of 2 Read data that just ended, a Confirm what was found that saved, confirmed_profile.json of the work folder, data_check_input.json of the read. Output: the read folder moves to the folder its inputs now name, with no read.json, then the worker command dataCheck runs with the role gathered in place of the folder, with config and the confirmed profile, its output folder that read folder. The worker loads the gathered file, runs DataCheckApply.Check and writes data_check.json, project_profile.json, plots.json and read_plotTable.json. No drawing is read again and Revit loads no gathered file, the press stays open and Revit free until the worker answers. On the answer read.json is written last with the inputs of the start and the profile, as in R791, so the Scope list names the confirmed areas and the next press reuses the read. A worker that fails or gives no answer keeps the step done with the line of R792, and the folder with no read.json is read again at the next press. The refusals before the worker starts are those of R792, shared with R791. ReadDataRun.ApplyConfirmedLater, started by ConfirmProfileStep.WrapLater, which ReadDataBody.For uses. The run id of the worker run is the run id of the press with "-confirm". Test: dotnet/SiteAdaptation.Tests/FAST15/R820_ConfirmInWorkerTests.cs. Not seen in Revit.
- **R821 The reuse line names the time.** Input: a press of 2 Read data on a raw read whose folder, settings file and confirmed values are those of a whole read. Output: the dry run says "Reuses the read of <HH:mm on d MMM>, nothing changed: " and what is unchanged, the time taken from the run id of the read, the run id itself when it holds no time. A read that is not whole by R639 is not reused, and the dry run names the count of files not read and the first by name and reason, as before. Test: dotnet/SiteAdaptation.Tests/FAST15/R820_ConfirmInWorkerTests.cs.
- **R822 The read by part.** Input: each file the worker command dataCheck opens. Output: one line "part | <kind> | <name> | <s> s" in the worker log per file, and per stage: gather, the write of the gathered file, the check, the load of a gathered file and the write of the four outputs. Names, kinds and seconds only. The release of memory, two full compacting collections, runs after a drawing, a workbook or a PDF, never after a peek of the head of a surface, rule or text file. On S1 a release took about 12 s once the road drawing was held, 19 surface files were peeked, so the read was 782 s and is now measured in the PR. No result changes, a collection frees only what nothing holds. CHOSEN by Code. Test: dotnet/SiteAdaptation.Tests/FAST15/R820_ConfirmInWorkerTests.cs, the part line.
- **R823 Gathered file keeps top outline candidates.** Input: the outline candidates of each drawing of the read, each a layer or a pair of layers with its faces. Output: data_check_input.json keeps, per drawing, the candidates whose plotOutline score of the scan is the top score of that drawing, every one of a tie. A drawing the scan cannot score, or whose top score is 0, keeps every candidate. The score is the faces that hold one plot number, from the texts, the label pattern and the faces alone, no confirmed value changes it, so the pick in a drawing, the pick across drawings and the break of a tie of R601 come out as on the whole list, and a Confirm takes the same outline. On S1 the other candidates were 922 of the 1,033 MB. Test: dotnet/SiteAdaptation.Tests/FAST15/R820_ConfirmInWorkerTests.cs, and on S1 outside the repo the four outputs of the check on the cut file equal those on the whole file.
